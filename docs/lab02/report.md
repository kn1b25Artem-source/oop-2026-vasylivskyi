## Мета роботи

Набути практичних навичок реалізації принципу інкапсуляції в об'єктно-орієнтованих програмах мовою C#, навчитися проєктувати класи з контрольованим доступом до їхнього внутрішнього стану, використовувати властивості, модифікатори доступу та сучасні можливості C# для ініціалізації й валідації даних. Сформувати вміння забезпечувати цілісність стану об'єктів, реалізовувати перевірку коректності даних під час їх створення та зміни, а також правильно організовувати взаємодію між об'єктами відповідно до принципів об'єктно-орієнтованого програмування.

## Завдання

Проєкт: вдосконалення програми обліку туристичних пропозицій та клієнтів.

1. **Інкапсуляція даних.** У класах `Tour` та `Client` реалізувати властивості замість відкритих полів.
2. **Валідація даних.** Перевірити країну, місто та ціну туру. Ціна повинна бути додатною, а текстові значення не можуть бути порожніми.
3. **Керування станом туру.** Додати властивість `IsAvailable` та методи `BookTour()` і `CancelBooking()`.

## Хід виконання

### 1. Інкапсуляція даних

Дані туру зберігаються в приватних полях `_country`, `_city` і `_price`, а зовнішній код працює з ними лише через публічні властивості `Country`, `City` і `Price`. У кожному `set` виконується перевірка, тому некоректне значення не потрапить у поле ні під час створення об'єкта, ні під час зміни.

Тур створюється конструктором з параметрами, тож об'єкт без країни, міста й ціни створити неможливо. Конструктор присвоює значення через властивості й повторно використовує ті самі перевірки.

У класі `Client` ім'я оголошено як `required`-властивість з аксесором `init`: компілятор не дасть створити клієнта без імені, а після створення ім'я лише читається.

Файл `Models/Tour.cs`:

```csharp
namespace TravelApp.Models;

/// <summary>
/// Туристична пропозиція (тур).
/// Дані зберігаються в приватних полях, а доступ до них іде через властивості з перевірками.
/// </summary>
public class Tour
{
    private string _country = string.Empty;
    private string _city = string.Empty;
    private decimal _price;

    /// <summary>
    /// Створює тур. Значення присвоюються через властивості,
    /// тому ті самі перевірки працюють і під час створення, і під час зміни.
    /// </summary>
    public Tour(string country, string city, decimal price)
    {
        Country = country;
        City = city;
        Price = price;
    }

    public string Country
    {
        get => _country;
        set => _country = RequireText(value, "Країна");
    }

    public string City
    {
        get => _city;
        set => _city = RequireText(value, "Місто");
    }

    /// <summary>
    /// Ціна туру, грн. Повинна бути більшою за нуль.
    /// </summary>
    public decimal Price
    {
        get => _price;
        set
        {
            if (value <= 0)
            {
                throw new ArgumentException("Ціна туру повинна бути більшою за нуль.");
            }

            _price = value;
        }
    }

    /// <summary>
    /// Клієнт, який забронював тур. Змінити ззовні не можна: set приватний.
    /// </summary>
    public Client? BookedBy { get; private set; }

    /// <summary>
    /// Чи доступний тур для бронювання. Обчислюється з BookedBy, тому стан завжди узгоджений.
    /// </summary>
    public bool IsAvailable => BookedBy is null;

    /// <summary>
    /// Бронює тур для клієнта. Повторне бронювання заборонене.
    /// </summary>
    public void BookTour(Client client)
    {
        ArgumentNullException.ThrowIfNull(client);

        if (!IsAvailable)
        {
            throw new InvalidOperationException($"Тур «{Country}, {City}» уже заброньовано.");
        }

        BookedBy = client;
    }

    /// <summary>
    /// Скасовує бронювання. Скасувати можна лише заброньований тур.
    /// </summary>
    public void CancelBooking()
    {
        if (IsAvailable)
        {
            throw new InvalidOperationException($"Тур «{Country}, {City}» не заброньовано, скасовувати нічого.");
        }

        BookedBy = null;
    }

    /// <summary>
    /// Короткий опис туру разом із його станом.
    /// </summary>
    public string GetInfo()
    {
        string status = BookedBy is null ? "доступний" : $"заброньовано: {BookedBy.Name}";
        return $"{Country}, {City} – {Price:0.##} грн [{status}]";
    }

    private static string RequireText(string value, string fieldName)
    {
        if (string.IsNullOrWhiteSpace(value))
        {
            throw new ArgumentException($"Поле «{fieldName}» не може бути порожнім.");
        }

        return value.Trim();
    }
}
```

Файл `Models/Client.cs`:

```csharp
namespace TravelApp.Models;

/// <summary>
/// Клієнт туристичної агенції.
/// </summary>
public class Client
{
    private string _name = string.Empty;

    /// <summary>
    /// Ім'я клієнта. required — без нього об'єкт не створити,
    /// init — задається лише під час створення, а далі тільки читається.
    /// </summary>
    public required string Name
    {
        get => _name;
        init
        {
            if (string.IsNullOrWhiteSpace(value))
            {
                throw new ArgumentException("Ім'я клієнта не може бути порожнім.");
            }

            _name = value.Trim();
        }
    }
}
```

### 2. Валідація даних

| Дані | Правило | Реакція на порушення |
|---|---|---|
| `Country`, `City` | не порожні й не з самих пробілів; зайві пробіли обрізаються | `ArgumentException` |
| `Price` | більше за нуль | `ArgumentException` |
| `Client.Name` | не порожнє | `ArgumentException` |

Виняток виникає до присвоєння, тому після невдалої спроби поле зберігає попереднє коректне значення.

### 3. Керування станом туру

Стан туру визначає властивість `BookedBy` — клієнт, який забронював тур. Її `set` приватний, тому змінити стан можна лише методами класу:

- `BookTour(Client client)` бронює тур для клієнта; якщо тур уже заброньовано, виникає `InvalidOperationException`;
- `CancelBooking()` скасовує бронювання; скасувати незаброньований тур не можна.

`IsAvailable` — обчислювана властивість лише для читання (`BookedBy is null`). Вона не має власного поля, тож суперечливий стан на кшталт «тур доступний, але заброньований» неможливий.

Спроби змінити стан напряму не компілюються (перевірено):

| Код | Помилка компілятора |
|---|---|
| `tour1.IsAvailable = false;` | CS0200: властивість лише для читання |
| `tour1.BookedBy = client2;` | CS0272: set-аксесор недоступний |
| `client1.Name = "Інше ім'я";` | CS8852: init-властивість задається лише під час створення |
| `Client noName = new();` | CS9035: не задано обов'язкову властивість `Name` |
| `Tour emptyTour = new();` | CS7036: конструктор вимагає країну, місто й ціну |

### 4. Демонстрація в головній програмі

`Program.cs` створює об'єкти, змінює ціну туру, бронює й скасовує бронювання, а також перехоплює (`try`/`catch`) помилки від некоректних даних і недопустимих операцій.

```csharp
using TravelApp.Models;

// Щоб українські літери (і, ї, є, ґ) правильно відображалися в консолі Windows
Console.OutputEncoding = System.Text.Encoding.UTF8;

// 1. Створення об'єктів.
// Тур створюється через конструктор: без країни, міста й ціни його не створити.
// У клієнта ім'я — required-властивість: без неї код не скомпілюється.
Tour tour1 = new("Італія", "Рим", 42300);
Tour tour2 = new("Туреччина", "Анталія", 28500);

Client client1 = new() { Name = "Олександр Бондаренко" };
Client client2 = new() { Name = "Катерина Литвин" };

Console.WriteLine("Тури:");
Console.WriteLine(tour1.GetInfo());
Console.WriteLine(tour2.GetInfo());

Console.WriteLine("\nКлієнти:");
Console.WriteLine(client1.Name);
Console.WriteLine(client2.Name);

// 2. Зміна властивості: нова ціна проходить перевірку в set
tour2.Price = 26900;
Console.WriteLine($"\nЗнижка: {tour2.GetInfo()}");

// 3. Керування станом туру — лише через методи BookTour() і CancelBooking()
Console.WriteLine("\nБронювання:");
tour1.BookTour(client1);
Console.WriteLine(tour1.GetInfo());

try
{
    tour1.BookTour(client2);
}
catch (InvalidOperationException ex)
{
    Console.WriteLine($"Помилка: {ex.Message}");
}

tour1.CancelBooking();
Console.WriteLine(tour1.GetInfo());

try
{
    tour1.CancelBooking();
}
catch (InvalidOperationException ex)
{
    Console.WriteLine($"Помилка: {ex.Message}");
}

// 4. Некоректні дані: об'єкт не переходить у неприпустимий стан
Console.WriteLine("\nПеревірка некоректних даних:");

try
{
    Tour wrongTour = new("Єгипет", "Хургада", -1000);
}
catch (ArgumentException ex)
{
    Console.WriteLine($"Помилка: {ex.Message}");
}

try
{
    tour2.City = "   ";
}
catch (ArgumentException ex)
{
    Console.WriteLine($"Помилка: {ex.Message}");
}

try
{
    Client wrongClient = new() { Name = "" };
}
catch (ArgumentException ex)
{
    Console.WriteLine($"Помилка: {ex.Message}");
}

Console.WriteLine($"Тур не змінився: {tour2.GetInfo()}");

// Такий код не скомпілюється — стан змінюється лише через методи класу:
// tour1.IsAvailable = false;     // CS0200: властивість лише для читання
// tour1.BookedBy = client2;      // CS0272: set-аксесор приватний
// client1.Name = "Інше ім'я";    // CS8852: init-властивість задається лише під час створення
```

## Аналіз: переваги інкапсуляції

- **Надійність.** Перевірки зібрано всередині класу, тож об'єкт не може опинитися в некоректному стані: тур з від'ємною ціною чи порожнім містом не створиться, а невдала зміна не зіпсує вже збережені дані.
- **Керованість.** Стан туру змінюється лише через `BookTour()` і `CancelBooking()`, які перевіряють правила: не можна забронювати тур двічі чи скасувати бронювання, якого немає.
- **Підтримуваність.** Зовнішній код не залежить від внутрішніх полів. Якщо зміниться правило (наприклад, мінімальна ціна) або спосіб зберігання даних, правити доведеться лише клас `Tour`, а не всі місця, де з ним працюють.

## Висновки

Під час виконання лабораторної роботи я реалізував принцип інкапсуляції в класах `Tour` і `Client`: дані сховано в приватних полях, а доступ до них надають властивості з перевірками. Застосовано конструктор з параметрами, властивості `get`/`set`, `init` і `required`, приватний `set` та обчислювану властивість. Керування станом туру реалізовано методами `BookTour()` і `CancelBooking()`, які не допускають переходу об'єкта в неприпустимий стан. Демонстрація в `Program.cs` показує, що некоректні дані відхиляються, а стан об'єктів лишається цілісним.
